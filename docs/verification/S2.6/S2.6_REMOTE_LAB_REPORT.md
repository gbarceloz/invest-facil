### A.2 Status

**PASS WITH LIMITATIONS.**

O núcleo de RLS, contexto e migration está validado no Lab. As limitações são de comprovação secundária:

1. **Advisors não acessados:** a CLI Supabase 3.2.0 existe, mas não há access token/Management API autenticada no ambiente. O Security Advisor, Performance Advisor e Health Advisor do Dashboard não foram consultados. O finding de `search_path` da função `apply_table_security` foi inspecionado diretamente no catálogo.
2. **TLS fim a fim não comprovado:** a conexão cliente → pooler usou TLS 1.3; `pg_stat_ssl` da sessão atrás do pooler retornou `ssl=false`, portanto não há evidência de TLS pooler → PostgreSQL. Não foi desabilitado TLS.
3. **Hikari/concorrência remotos:** a aplicação remota usou Hikari e passou startup/health/auth; o teste direto de reutilização de conexão, rollback e concorrência foi executado localmente na S2.5. Não foi possível inspecionar `current_setting` de uma conexão Hikari da aplicação remota sem criar endpoint/configuração temporária.
4. **DemoDataInitializer:** bloqueado no profile `prod`; não foi executado no Lab. O comportamento foi validado localmente na S2.5.
5. **E2E de navegador:** não executado nesta missão; a validação remota foi HTTP + JDBC real.

### A.3 Decisão

A V6 está **validada no Lab** e pode seguir para a próxima etapa de preparação de produção, mas **não está aprovada para produção** até S2.7 concluir TLS fim a fim, Advisors e o gate operacional.
